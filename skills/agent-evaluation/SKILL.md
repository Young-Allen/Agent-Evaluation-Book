# Agent 工程评测

把业务成功条件变成可执行的检查，把异常变成有证据的归因与改进。使用项目已有的运行方式、数据格式和工具；不预设语言、Agent 框架或观测平台。

## 1. 先决定本次交付范围

结合用户请求与仓库证据，选择本次需要的工作，不要求每次覆盖全部模式：

| 请求 | 主要工作 | 按需读取 |
|---|---|---|
| 评测方案、评测集、版本回归、发布门禁 | 定义任务、证据、评分和比较口径 | [离线设计](references/offline.md)、[任务模板](assets/task.yaml) |
| A/B、影子、巡检、线上指标 | 明确受影响用户、执行环境和结果解释方式 | [线上设计](references/online.md) |
| 失败分析、分数下降、Trace 排查 | 复现、竞争假设、证据定位、回归样本 | [归因与体系审查](references/diagnosis.md) |
| 评测体系审查、成熟度分析 | 按实际证据找缺口与优先动作 | [归因与体系审查](references/diagnosis.md) |

用户只要分析时交付分析；要求实现时，把必要的 Task、评分逻辑、运行入口和结果记录落到项目中。模板仅是起点，不假装项目已经支持模板字段。

## 2. 收集足以启动的项目证据

先读取适用的 AGENTS.md、项目说明、Agent 入口、工具定义、已有测试与评测、可用 Trace。查找任务状态、最终产物、版本标识和环境重置方式。

建立简短的上下文记录：

- 用户目标、典型任务、不可接受的结果，以及允许变化的输出形式。
- 输入数据、权限、外部依赖、执行副作用和成功证据的位置。
- 本次变更范围、基线与候选版本、样本与标准的版本。
- 可用运行环境、调用成本、执行次数预算和已有授权。

区分已确认事实、工作假设、缺失信息。缺数据不等于能力不存在；没有指标不等于指标为零。缺业务口径时，可以先产出任务骨架与待定项，不编造上线阈值或真实结果。

## 3. 把质量要求变成可检查的契约

每个 Task 明确输入、初始状态、成功条件、证据和评分方式。分别判断任务结果与关键过程；只在业务必要时约束执行路径，允许等价的合理实现。

每条检查规则说明检查对象、条件、所需证据和重要性。数字与状态优先使用可重复的程序检查；开放质量可采用明确 Rubric 的人工或模型判定，并核对判定分歧。

缺少证据、评分器错误、执行环境故障和 Agent 失败分别记录。未知不能静默计为通过。硬性规则不允许被其他维度的高分抵消。

## 4. 执行时保留可比较条件

执行前明确本次范围、命令、样本、版本、重试与预算。在既有授权内运行所需评测；分析请求不自动扩展为付费模型批跑、生产流量实验或真实工具写入。

比较基线与候选时保持任务、数据、环境和判定标准可比；每次 Trial 重置有影响的状态。若标准变化，尽可能用新标准重评两版，不能把标准变化造成的差异归因于 Agent。

报告有效运行、基础设施错误、待判定、重试、失败分布与成本。单次改善不足以证明稳定提升；重复次数由风险、成本和结果波动决定。

遇到超出约定成本、意外生产写入、无法隔离的状态污染时停止相关执行，保留已获得证据。凭已有授权继续完成其他不受影响的分析。

## 5. 让每个问题进入改进流程

同一案例同时检查两件事：Agent 哪一步偏离要求，以及样本或规则是否误判、缺漏。按证据分别提出 Agent 修改和评测修订；一个案例可以进入两条路径。

修复建议关联复现任务和相邻反例；结案需要修复后的证据。成功案例可用于解释质量边界，历史失败可用于回归，新场景可用于补齐覆盖。避免只积累问题标签而没有后续动作。

## 6. 交付与完成条件

按任务规模选择 [报告模板](assets/report.md) 中必要的部分，不为简单请求生成整套文档。交付应包含：

- 结论与适用范围；能追溯到代码、数据、运行记录的证据。
- 已产出的任务、规则、实现或分析文件，以及复现方式。
- 实际运行过什么、观察到什么、哪些尚未运行或仍无法判断。
- 影响决策的限制，以及按影响和工作量排序的下一步。

方案交付以输入、标准、证据、执行方式和责任明确为完成；实现交付还需在可用环境内验证运行与评分逻辑。没有实际运行时只能称为方案或待验证实现。离线通过不能直接宣布线上业务价值成立，体系审查也不自动批准发布。

## 来源与边界

框架受美团技术团队[《Agent 评测白皮书》系列01](https://tech.meituan.com/2026/09/10/Agent-Evaluation-White-Paper-01.html)启发：离线、线上评测与监控、案例归因和观测共同工作，Agent 与评测体系分别迭代。指标术语参考 [Anthropic Agent evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)。本 skill 的模板、工程约束与决策流程为补充设计，不是两篇文章的官方实现。

本 skill 支持 Agent 应用的工程评测，不代替所有软件测试、性能容量评估或特定行业审核。它不附带生产连接器和通用跑分脚本；实际实现根据目标项目的接口与依赖选择。
